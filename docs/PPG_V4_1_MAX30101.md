# SafeBand AI — PPG V4.1: MAX30101-Domain HR Estimation

## Purpose

PPG V4.1 is the corrected/diagnostic successor to the first V4 implementation.
It uses the Pulse Transit Time PPG Dataset as a MAX30101-domain reference and
moves the project closer to the planned MAX30102 optical hardware.

It is **not MAX30102 validation**. Actual MAX30102 recordings remain necessary.

## Dataset basis

The PTT dataset contains 22 healthy subjects and 66 recordings across sitting,
walking and running. Its documented hardware includes two Maxim MAX30101 PPG
sensors, red/infrared/green optical channels, an MPU-9250 IMU and ECG
annotations.

The distributed PPG representation is 500 Hz. The six PPG columns are:

| V4 name | PTT column | Meaning |
|---|---|---|
| distal_red | pleth_1 | distal red |
| distal_ir | pleth_2 | distal infrared |
| distal_green | pleth_3 | distal green |
| proximal_red | pleth_4 | proximal red |
| proximal_ir | pleth_5 | proximal infrared |
| proximal_green | pleth_6 | proximal green |

## Target

The primary target is **heart rate in BPM**.

For each 8-second window, ECG R-peak annotations are converted into a robust
median-RR HR target. The ECG waveform itself is never supplied to the model.

## Windowing

- Window: 8 seconds
- Shift: 2 seconds
- PPG: 500 Hz
- ACC: 500 Hz
- GYRO: 500 Hz

## Feature representation

V4.1 uses 6 optical channels plus motion:

- waveform statistics
- robustly normalized PPG morphology
- 0.5–5 Hz spectral features
- dominant-frequency HR candidates
- peak-derived HR candidates
- AC/DC representation
- red/IR/green correlations
- distal/proximal correlations
- accelerometer features
- gyroscope features
- PPG-to-motion correlations

AC/DC is a representation feature only. It is **not** a clinical SpO2
equation.

## SpO2 handling

The PTT dataset provides start/end SpO2 numerics for activities. V4.1 does
not copy these values into every window. A continuous SpO2 model requires
appropriately timed reference labels or a separate calibration protocol.

## V4.1 correction

The first V4 implementation used ordinary lexical sorting for subject IDs.
That gives an order such as:

```text
s1, s10, s11, ..., s19, s2, s20, ...
```

V4.1 uses numeric subject ordering:

```text
s1, s2, s3, ..., s22
```

This makes the deterministic 60/20/20 split explicit and easier to audit.

The original V4 report should be retained as historical evidence; V4.1 is a
new experiment and its metrics must not be silently substituted for V4.

## Training

```powershell
python tools/prepare_ptt_hr_v4.py `
  --ptt-root datasets/raw/PTT `
  --out datasets/processed/ptt/ppg_v4_features_v4_1.csv `
  --summary-out datasets/processed/ptt/ppg_v4_prepare_v4_1.json
```

```powershell
python tools/train_ppg_v4_ptt.py `
  --input datasets/processed/ptt/ppg_v4_features_v4_1.csv `
  --model-out models/ppg_v4/ppg_v4_1_max30101.joblib `
  --report-out models/ppg_v4/ppg_v4_1_max30101_report.json `
  --predictions-out models/ppg_v4/ppg_v4_1_test_predictions.csv
```

Then run diagnostics:

```powershell
python tools/evaluate_ppg_v4.py `
  --predictions models/ppg_v4/ppg_v4_1_test_predictions.csv `
  --report-out models/ppg_v4/ppg_v4_1_test_diagnostics.json
```

## How to read the scores

This is a regression problem, so there is no single classification-style
"accuracy" number.

| Metric | Meaning | Desired direction |
|---|---|---|
| MAE | average absolute HR error | lower |
| RMSE | error emphasizing large mistakes | lower |
| R² | variance explained vs constant-mean baseline | higher |
| ±3 BPM | predictions within 3 BPM | higher |
| ±5 BPM | predictions within 5 BPM | higher |
| ±10 BPM | predictions within 10 BPM | higher |
| Bias | average signed error | closer to 0 |
| Median AE | typical absolute error | lower |
| P90 AE | error below which 90% of cases fall | lower |
| Max AE | largest observed error | lower |

Do not judge the model from validation alone. The most important research
result is the completely held-out subject test set.

## Model selection

Four classical regressors are compared:

1. Ridge
2. Random Forest
3. Extra Trees
4. HistGradientBoosting

The model with the lowest validation MAE is selected.

The final selected estimator is then refit using train + validation subjects.
The held-out test subjects remain untouched until that point.

## Calibration

An affine calibration is fitted from validation predictions only:

```text
calibrated = slope * raw_prediction + intercept
```

It is retained only if validation MAE strictly improves.

This is an experimental calibration mechanism, not MAX30102 calibration.

Actual MAX30102 calibration will be performed later using real sensor recordings
and a separately defined calibration/validation protocol.

## Diagnostics

`evaluate_ppg_v4.py` does not retrain anything. It reports:

- overall held-out metrics
- activity-level metrics
- subject-level metrics
- recording-level metrics
- error quantiles

This is important because a good aggregate MAE can hide one difficult activity
or one difficult subject.

## Research positioning

```text
PPG-DaLiA / Empatica E4
        ↓
PPG V3 E4 reference
        ↓
PTT / MAX30101
        ↓
PPG V4.1 MAX30101-domain reference
        ↓
real MAX30102 recordings
        ↓
hardware-domain validation
        ↓
validation-based calibration / optional fine-tuning
```

V4.1 therefore improves hardware relevance without making the unsupported
claim that MAX30101 results are equivalent to MAX30102 results.
